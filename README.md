# Задачи

Таск-трекер в духе Microsoft To Do для одного человека или для семьи и небольшой команды.

- **Приложения**: Windows (живёт в трее, уведомления), Android (уведомления, виджет на рабочий стол), браузер (PWA). Один код на Flutter.
- **Работает офлайн**: все правки сначала в локальной базе, синхронизация — когда есть связь. Конфликты решаются по каждому полю: побеждает более поздняя правка, даже если часы устройства сбиты.
- **Без сервера**: на первом экране можно выбрать «Использовать локально» — получится задачник для одного человека на этом устройстве. Подключиться к серверу можно позже, задачи переедут туда.
- **Со своим сервером**: один файл `todod` — база, синхронизация, пользователи и веб-версия. Первый, кто подключится к новому серверу, становится администратором и заводит остальных прямо в приложении.

Что умеет: разделы «Сегодняшний день», «Важные», «Запланировано», «Задачи», «Мои дела» (приватные задачи); свои списки (можно назначить исполнителя списка); подзадачи и чек-листы; сроки, напоминания и повторение; общие и приватные задачи, исполнители, режим «Только свои»; темы, акцентный цвет, фоновая картинка.

## Как начать

1. **Сервер** (если нужен) — см. [DEPLOY.md](DEPLOY.md): скопировать папку с сервером на Linux-машину и выполнить `sudo bash install.sh`. Скрипт напечатает адрес сервера и ключ доступа.
2. **Приложение**: при первом запуске ввести адрес и ключ доступа (или нажать «Использовать локально»).
3. **Первый вход** на новый сервер — создание администратора (имя и пароль). Дальше администратор добавляет пользователей: Настройки → «Пользователи».
4. **Браузер**: открыть адрес сервера и ввести ключ доступа.

## Устройство

| Папка | Что там |
| --- | --- |
| `app/` | клиент на Flutter (Windows, Android, веб) |
| `server/` | сервер на Go: SQLite, синхронизация, пользователи, встроенный веб-клиент |
| `deploy/` | установка на Linux (systemd), Docker, пример для Caddy |
| `tools/` | скрипты сборки для Windows (PowerShell) |
| `docs/API.md` | API сервера |

- **Клиент**: все операции идут в локальную базу (SQLite на устройствах, IndexedDB в браузере). При связи с сервером клиент сначала отправляет свои изменения, затем забирает чужие.
- **Сервер**: один бинарник без зависимостей (Go, SQLite в режиме WAL). API защищён ключом доступа: без него сервер не отвечает вовсе. Пароли — bcrypt; пять неверных попыток — пауза минуту.
- **Сертификат**: по умолчанию сервер сам создаёт самоподписанный сертификат, а приложения проверяют отпечаток его ключа (он — вторая часть ключа доступа). Можно поставить сервер за обратный прокси с настоящим сертификатом — тогда ключ доступа короче, а браузер не показывает предупреждение.

## Сборка

Нужны: Flutter (с Dart 3.13 и новее), Go (1.23+), для Android — JDK 17 и Android SDK, для Windows — Visual Studio Build Tools с компонентом «Разработка классических приложений на C++».

Скрипты в `tools/` (PowerShell, Windows); на Linux и macOS те же команды выполняются вручную.

| Что | Команда | Результат |
| --- | --- | --- |
| Веб-клиент | `tools\build-web.ps1` | `app\build\web\` |
| Сервер (Linux, amd64 и arm64) со встроенным веб-клиентом | `tools\build-server.ps1` | `dist\server\` — бинарники и всё для установки |
| Windows | `flutter build windows --release` в `app\` | `app\build\windows\x64\runner\Release\` |
| Android | `tools\build-android.ps1` | `app\build\app\outputs\flutter-apk\app-release.apk` |
| Значки | `dart run tool/gen_icons.dart` в `app\` | значки всех платформ |

Сервер без веб-клиента (для разработки): `go build ./cmd/todod` в `server\` — вместо веб-версии будет страница-заглушка.

Ключ подписи Android (`app\android\todo-release.jks` и `key.properties`) создаётся при первой сборке. **Сохраните его и не публикуйте**: без того же ключа обновить установленное приложение нельзя.

Идентификатор приложения — `todo.app` (Android `applicationId`, Windows). Если будете распространять свою сборку, поменяйте его на свой (`app/android/app/build.gradle.kts`, папка `app/android/app/src/main/kotlin/todo/app`, константы в `app/lib/platform/platform_io.dart`).

## Принятые решения

- **Первый пользователь — администратор.** Пока на сервере нет пользователей, любой, у кого есть ключ доступа, может создать первого. Поэтому ключ доступа держите при себе, пока не настроите сервер.
- **Администраторов может быть несколько**; последнего нельзя ни удалить, ни разжаловать. У администратора всегда есть пароль, у остальных — по желанию.
- **Режим администратора** — переключатель в настройках: в нём администратор может править любые общие задачи и списки. Чужие приватные задачи не видны никому.
- **Исполнитель** может закрыть и переоткрыть задачу и добавить её в «Сегодня»; остальное меняет автор.
- **Закрытие снимает срок** (и повторение): переоткрытая задача ведёт себя как новая. Задача, закрытая сегодня, остаётся в «Сегодня» до конца дня.
- **Срок и напоминание нельзя поставить на прошедший день.**
- **Удалённый пользователь**: его приватные задачи удаляются, общие переходят к администратору; его устройства перестают синхронизироваться, но данные на них остаются.
- **Часовой пояс** для дат задаёт администратор (Настройки → Администратор); пусто — каждое устройство считает по своему поясу. В локальном режиме — пояс устройства.
- **Локальный режим**: нет пользователей, совместной работы и синхронизации. Задачи, списки и настройки при подключении к серверу переходят к пользователю, под которым вы войдёте.
- **Фоновая картинка и оформление виджета** хранятся только на устройстве; тема и цвета синхронизируются.
- **Уведомления Windows.** Плагин `flutter_local_notifications` для Windows требует компонент ATL из Visual Studio, поэтому его нативная часть отключена (`app/third_party/flutter_local_notifications_windows`), а уведомления показываются напрямую через системный API.
- **Напоминания, пропущенные до входа на устройстве**, не показываются. Опоздавшее напоминание показывается, если ему не больше 48 часов; напоминание по сроку — только в день срока.
