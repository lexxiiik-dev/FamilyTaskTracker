# Как поставить свой сервер

Сервер — это одна программа `todod`. Внутри неё всё: база задач, синхронизация между устройствами, пользователи и веб-версия (открывается в браузере по адресу сервера). Отдельно ставить базу данных, веб-сервер или что-то ещё не нужно.

Понадобится компьютер или VPS с Linux, который виден с ваших устройств: арендованный сервер в интернете или домашний компьютер в той же сети. Хватит самого слабого VPS: сервер занимает несколько десятков мегабайт памяти.

Есть три способа — выберите один:

| Способ | Когда подходит |
| --- | --- |
| [А. Обычная установка](#а-обычная-установка-рекомендуется) | Linux с systemd (Ubuntu, Debian и т. п.). Проще всего. |
| [Б. С доменом и настоящим сертификатом](#б-с-доменом-и-настоящим-сертификатом) | У вас есть домен и вы не хотите предупреждения браузера о сертификате. |
| [В. Docker](#в-docker) | На сервере уже всё в Docker. |

## Что нужно заранее

Папка `server` из релиза (или собранная командой `tools\build-server.ps1` в `dist\server`). В ней:

- `todod-linux-amd64`, `todod-linux-arm64` — программа для обычных серверов и для ARM (Raspberry Pi и т. п.);
- `install.sh` — установка;
- `todod.service`, `todod-backup.service`, `todod-backup.timer` — службы systemd;
- `backup.sh`, `restore.sh` — копия базы и восстановление;
- `Dockerfile`, `docker-compose.yml`, `Caddyfile.example` — для способов Б и В.

## А. Обычная установка (рекомендуется)

**1. Скопируйте папку на сервер.** С вашего компьютера (вместо `1.2.3.4` — адрес сервера):

```bash
scp -r server root@1.2.3.4:/root/todo-server
```

**2. Запустите установку** на сервере:

```bash
ssh root@1.2.3.4 "cd /root/todo-server && sudo bash install.sh"
```

Скрипт сам:

- поставит программу в `/opt/todod`, а базу — в `/var/lib/todod`;
- выберет свободный порт (8443, если он не занят) и откроет его в брандмауэре `ufw`, если тот включён (другие правила и программы не трогает);
- создаст ключ доступа и сертификат в `/etc/todod`;
- включит службу и ежедневную копию базы.

В конце он напечатает:

```
  Адрес сервера:  https://1.2.3.4:8443
  Ключ доступа:   3f9c…e1.Qm7…xA
```

**Сохраните эти данные** — их вводят в приложении. Потом их всегда можно посмотреть командой:

```bash
sudo /opt/todod/todod info -config /etc/todod/config.json
```

**3. Первый вход.** Откройте приложение на ПК или телефоне, введите адрес сервера и ключ доступа. Сервер новый, поэтому приложение предложит создать первого пользователя — он станет администратором. Пока вы этого не сделали, никому не сообщайте ключ доступа.

**4. Остальные пользователи.** В приложении: значок пользователя → «Настройки» → «Пользователи» → «Добавить». Каждому сообщите адрес сервера и ключ доступа (они есть в настройках у администратора), пусть войдут под своим именем.

**Веб-версия** открывается по тому же адресу в браузере: `https://1.2.3.4:8443`. Сертификат у сервера свой (самоподписанный), поэтому браузер при первом входе предупредит, что подключение «не защищено». Это ожидаемо: нажмите «Дополнительно» → «Перейти на сайт». Приложения на ПК и телефоне такого предупреждения не показывают: они проверяют отпечаток ключа сервера (вторая часть ключа доступа после точки). Чтобы браузер не ругался, используйте способ Б.

Параметры установки можно задать заранее:

```bash
sudo PORT=9443 PUBLIC_URL=https://tasks.example.com:9443 bash install.sh
```

## Б. С доменом и настоящим сертификатом

Нужен домен (например, `tasks.example.com`), указывающий на сервер, и открытые порты 80 и 443. Сертификат Let's Encrypt будет получать [Caddy](https://caddyserver.com/docs/install).

**1. Установите todod за прокси:**

```bash
cd /root/todo-server && sudo PROXY=1 PUBLIC_URL=https://tasks.example.com bash install.sh
```

Сервер будет слушать только `127.0.0.1:8080` (снаружи его не видно), а ключ доступа станет короче — без отпечатка после точки.

**2. Установите Caddy** по инструкции с его сайта и замените `/etc/caddy/Caddyfile` на:

```
tasks.example.com {
	reverse_proxy 127.0.0.1:8080
}
```

**3. Перезапустите Caddy:** `sudo systemctl reload caddy`.

Адрес сервера для приложений и браузера — `https://tasks.example.com`. Дальше — как в способе А, с шага 3.

С nginx тоже работает: проксируйте всё на `http://127.0.0.1:8080` и передавайте заголовок `X-Forwarded-For`.

## В. Docker

В папке с сервером:

1. Откройте `docker-compose.yml` и впишите в `PUBLIC_URL` адрес, по которому сервер будут видеть пользователи (например, `https://1.2.3.4:8443`).
2. Запустите:

   ```bash
   docker compose up -d
   ```

3. Посмотрите адрес и ключ доступа:

   ```bash
   docker compose logs todod
   ```

База и ключи лежат в томе Docker `todod-data`. Копия базы:

```bash
docker compose exec todod todod backup /data/backup.sqlite -config /data/config.json
docker compose cp todod:/data/backup.sqlite ./backup.sqlite
```

Образ собран для amd64; для ARM замените в `Dockerfile` имя файла на `todod-linux-arm64`.

## Обслуживание

| Что сделать | Команда |
| --- | --- |
| Состояние службы | `systemctl status todod` |
| Журнал | `journalctl -u todod -n 50` |
| Адрес и ключ доступа | `sudo /opt/todod/todod info -config /etc/todod/config.json` |
| Забыт пароль администратора | `sudo -u todod /opt/todod/todod passwd "Имя" "новый пароль" -config /etc/todod/config.json` |
| Копия базы прямо сейчас | `sudo -u todod /opt/todod/backup.sh` |
| Восстановить из копии | `sudo /opt/todod/restore.sh /var/lib/todod/backups/todo-….sqlite` |

- **Копии базы** делаются каждый день в 03:30 в `/var/lib/todod/backups`, хранятся 7 последних. Сервер останавливать не нужно. Для надёжности время от времени забирайте копию на другой компьютер.
- **После восстановления** устройства сами заберут все данные заново и повторно отправят свои открытые задачи, так что правки, сделанные после копии, не потеряются.
- **Обновление**: скопируйте новую папку с сервером и снова запустите `sudo bash install.sh`. Настройки, ключ доступа и база сохранятся.
- **Срок хранения закрытых задач** (по умолчанию 30 дней) и часовой пояс для дат меняет администратор в приложении: Настройки → раздел «Администратор».

## Переезд на другой сервер

1. Сделайте копию базы и заберите папку `/etc/todod` (там ключ доступа и сертификат) и файл копии.
2. На новом сервере установите todod как обычно, остановите службу (`sudo systemctl stop todod`), положите на место старую `/etc/todod` (с владельцем `root:todod`) и восстановите базу через `restore.sh`.
3. На устройствах поменяйте адрес сервера: администратор — в настройках («Адрес сервера на этом устройстве»), остальные — выйти и подключиться заново. Ключ доступа остаётся прежним, потому что сертификат тот же.

## Если что-то не так

- **Приложение пишет «Не удалось подключиться»**: проверьте адрес (с `https://` и портом) и ключ доступа целиком, включая часть после точки. Проверьте, что порт открыт в брандмауэре сервера и у хостинга.
- **Сервер «молчит»** на запросы из браузера к `/v1/...` — так и задумано: без ключа доступа API не отвечает. Сама веб-версия по адресу сервера открывается без ключа.
- **Порт занят**: задайте другой — `sudo PORT=9443 bash install.sh` (при первой установке).
