# API сервера

Сервер (`server/`, программа `todod`) — это база, синхронизация, пользователи и веб-клиент в одном процессе. API находится по адресу `<сервер>/v1/...`, веб-клиент — по корневому адресу `<сервер>/`.

## Доступ

- Каждый запрос к API несёт заголовок `X-Access-Key: <ключ доступа>`. Без него (или с неверным) сервер рвёт соединение без ответа — для посторонних API «молчит». Веб-клиент отдаётся без ключа.
- После входа запросы несут `Authorization: Bearer <токен устройства>`. Токен выдают `/v1/setup` и `/v1/login`.
- Ключ, который вводит пользователь в приложении, — `<ключ доступа>.<отпечаток>` или просто `<ключ доступа>`:
  - с отпечатком — сервер работает по HTTPS со своим (самоподписанным) сертификатом, а приложение доверяет только ключу с этим отпечатком (base64url от SHA-256 открытого ключа сертификата, SubjectPublicKeyInfo); имя хоста не проверяется, поэтому сертификат работает по любому адресу;
  - без отпечатка — сервер стоит за обратным прокси с обычным сертификатом, приложение проверяет его как браузер.

**Ошибки доступа**

| Ответ | Значение |
| --- | --- |
| `401 {"error":"bad_token"}` | токен неизвестен (например, после смены пароля), нужно войти заново |
| `401 {"error":"user_deleted"}` | пользователь удалён: устройство прекращает синхронизацию, локальные данные остаются |
| `403` | нужны права администратора |

## Модель

Задача и список передаются одинаково:

```json
{
  "id": "uuid",
  "creator_id": "id пользователя",
  "is_private": false,
  "created_at": 1794300000000,
  "f": { "title": "Купить корм", "status": "open", "deadline": "2026-11-12" },
  "t": { "title": 1794300000000, "status": 1794300000000, "deadline": 1794300005000 },
  "d": ["title"],
  "rev": 42,
  "updated_at": 1794300005000
}
```

- `f` — значения полей.
- `t` — время последней правки каждого поля. По нему разрешаются конфликты: побеждает более поздняя правка, отдельно по каждому полю.
- `d` — только в запросах клиента: поля, изменённые на устройстве и ещё не подтверждённые сервером. Сервер сливает только их; остальное содержимое `f` используется, если записи на сервере нет (создание и восстановление очищенной задачи).
- `rev` — номер изменения на сервере, по нему строится курсор.

Поля задачи (`f`):

| Поле | Тип | Примечание |
| --- | --- | --- |
| `title`, `description` | строка | |
| `checklist` | массив `{text, done}` | порядок сохраняется |
| `parent_id` | строка | основная задача, один уровень |
| `list_id` | строка | пусто — раздел «Задачи» |
| `assignee_id` | строка | у приватной всегда равен `creator_id` |
| `deadline` | `ГГГГ-ММ-ДД` или пусто | при закрытии задачи снимается |
| `reminder_at` | число, мс | 0 — нет |
| `status` | `open` \| `done` | время закрытия — `t.status` |
| `is_important`, `in_today` | флаг | |
| `recurrence` | объект или `null` | см. ниже |
| `sort_order` | число | |
| `deleted` | флаг | пометка удаления |

Поля списка: `name`, `assignee_id`, `sort_order`, `deleted`, `delete_tasks` (при удалении: удалить задачи списка, иначе они переходят в общий раздел).

Правило повторения: `{"type":"daily"}`, `{"type":"weekly","days":[1,3,5]}` (1 — понедельник), `{"type":"interval","n":2,"unit":"day|week|month"}`, `{"type":"yearly"}`. Следующий экземпляр создаёт клиент при закрытии; его ID — UUIDv5 от ID закрытой задачи, поэтому два устройства офлайн создают один и тот же экземпляр.

Настройки пользователя и глобальные настройки — словари `ключ → {"v": значение, "t": время}`, сливаются так же, по времени.

Ключи настроек пользователя: `theme`, `accent`, `plate`, `border`, `plate_dark`, `border_dark`, `deadline_time` (`ЧЧ:ММ`), `home_list`, `view_mode` (`all`/`mine`), `admin_mode`, `list_order`.
Глобальные: `retention_days` (срок жизни завершённых задач, по умолчанию 30), `tz` (часовой пояс для дат, например `Europe/Moscow`; пусто — каждое устройство считает по своему поясу).

## Первый запуск и вход

### `GET /v1/hello`

Проверка адреса и ключа, список пользователей для экрана входа.

```json
{ "time": 1794300000000, "epoch": "a1b2c3d4e5f60718", "setup": false,
  "users": [ { "id": "…", "name": "Аня", "is_admin": true, "has_password": true, "avatar_ver": 1794325434289 } ] }
```

`setup: true` — пользователей ещё нет: первый станет администратором.

### `POST /v1/setup`

Тело: `{"name": "…", "password": "…", "device": "имя устройства"}`. Работает, только пока на сервере нет пользователей. Создаёт администратора (пароль обязателен, от 4 символов) и сразу входит: `{"ok": true, "token": "…", "user_id": "…"}`. Повторно — `400 {"error": "Сервер уже настроен"}`.

### `POST /v1/login`

Тело: `{"user_id": "…", "password": "…", "device": "имя устройства"}`. Пароль проверяется по bcrypt; пять ошибок с одного адреса — пауза 60 с. Ответ `{"ok": true, "token": "…", "user_id": "…"}`, ошибка — `403 {"error": "Неверный пароль", "need_password": true}`.

### `POST /v1/me/password`

Смена своего пароля: `{"old": "…", "new": "…"}` (пустой `new` — вход без пароля; администратору нельзя). Ответ `{"ok": true, "token": "…"}` — новый токен этого устройства; остальные устройства пользователя входят заново.

## Синхронизация

### `POST /v1/changes`

Отправка изменений. Сначала применяются списки, затем основные задачи, затем подзадачи.

```json
{ "now": 1794300000000,
  "tasks": [ { "id": "…", "creator_id": "…", "is_private": false, "created_at": 0, "f": {}, "t": {}, "d": ["title"] } ],
  "lists": [],
  "settings": { "view_mode": { "v": "mine", "t": 1794300000000 } } }
```

`now` — текущее время клиента. Сервер считает поправку часов (`время сервера − now`) и переводит все времена правок в свои часы; время из будущего обрезается. Так сравнивается время правки, а не время выхода в сеть, и сбитые часы устройства не мешают.

Ответ:

```json
{ "time": 1794300000123, "tasks": [ … ], "lists": [ … ], "rejected": ["id"], "settings": { … } }
```

`tasks` и `lists` — итоговые версии всех затронутых записей (включая изменённые каскадом). Клиент принимает их целиком, кроме полей, которые успел изменить после отправки. `rejected` — записи, в которых часть правок отклонена (нет прав, нарушено правило).

Права и правила проверяет сервер:

- автор — любые поля; исполнитель — `status` и `in_today`; администратор с `admin_mode` — любые общие задачи и списки;
- чужие приватные задачи недоступны никому, включая администратора;
- у приватной задачи исполнитель — автор; `is_private` после создания не меняется;
- задача в списке с исполнителем получает исполнителя списка;
- приватную задачу нельзя положить в список чужого исполнителя;
- подзадача наследует список и приватность основной; вложенность — один уровень;
- основную задачу нельзя закрыть при открытых подзадачах; удаление основной удаляет подзадачи;
- закрытая задача теряет срок и повторение (переоткрытая ведёт себя как новая);
- смена исполнителя списка переносит его задачи; удаление списка удаляет задачи или переносит их в общий раздел.

### `GET /v1/changes?cursor=N`

Изменения после курсора.

```json
{ "time": 0, "epoch": "…", "cursor": 57, "more": false, "me": "…",
  "tasks": [ … ], "lists": [ … ],
  "users": [ … ],
  "settings": { "theme": { "v": "dark", "t": 0 } },
  "global": { "retention_days": { "v": 30, "t": 0 }, "tz": { "v": "", "t": 0 } } }
```

- Приходят все общие задачи и только свои приватные. Пометки удаления приходят как записи с `deleted: true`.
- Пользователи отдаются полностью: отсутствующий в списке удалён.
- За один запрос — до 500 записей; при `more: true` запрос повторяют с новым курсором.
- `epoch` — идентификатор базы. Если он сменился (восстановление из копии), клиент обнуляет курсор, забирает всё заново и повторно отправляет свои открытые задачи.
- Очистка завершённых задач по сроку жизни сюда не попадает: у клиентов задача остаётся в архиве.

### Аватарки

- `GET /v1/avatar/{id}?v=<avatar_ver>` — превью JPEG 128×128 (нужен только ключ доступа).
- `POST /v1/avatar` — тело: картинка (JPEG, PNG, WEBP или GIF, до 4 МБ); сервер хранит квадратное превью.

## Администратор

Доступно пользователю с `is_admin`.

| Запрос | Назначение |
| --- | --- |
| `GET /v1/admin/connect-info` | `{"url": "…", "key": "<ключ>.<отпечаток>"}` — данные для подключения новых устройств |
| `GET /v1/admin/settings` | `{"retention_days": 30, "tz": ""}` |
| `PUT /v1/admin/settings` | изменить срок жизни завершённых задач и часовой пояс |
| `POST /v1/admin/users` | `{"name", "password", "is_admin"}` — новый пользователь (пароль можно пустой, кроме администратора) |
| `PATCH /v1/admin/users/{id}` | `{"name"?, "password"?, "is_admin"?}` — изменить; `password: ""` убирает пароль; после смены пароля устройства пользователя входят заново |
| `DELETE /v1/admin/users/{id}` | удалить пользователя |

Ограничения: имена без учёта регистра не повторяются; должен остаться хотя бы один администратор; у администратора всегда есть пароль; себя удалить нельзя.

Удаление пользователя: его приватные задачи удаляются; общие задачи и списки переходят к первому администратору как к автору; в его задачах исполнителем становится администратор; у списков поле исполнителя очищается. Устройства удалённого пользователя получают `401 user_deleted` и работают дальше автономно.

## Фоновые задачи сервера

- Раз в час удаляются завершённые задачи старше `retention_days` дней — без пометок удаления.
- Пометки удаления хранятся 180 дней.
- Если устройство пришлёт правку уже очищенной задачи, сервер создаст её заново.
